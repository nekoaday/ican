# 保额罗盘 InsureCompass

**AI 家庭保险保障体检助手**：通过可解释的确定性公式测算定期寿险、重疾险的参考目标与待补缺口，再由服务端接入的 AI 助手解释结果。

本项目用于金融科技竞赛展示与保险保障教育，不提供保险销售、核保、理赔承诺或具体产品报价。默认参数是可调整的项目假设，不是行业统一标准。

## 功能

- 中文响应式表单：年龄、收入、家庭人数、受扶养人数、房贷、已有保障及高级财务参数。
- 确定性测算：金额由代码产生，与大模型调用分离。
- 三种情景对比、已有保障与缺口图表、计算依据明细及浏览器 PDF 打印。
- 真实模型 API 聊天：浏览器请求本项目 `/api/chat`；服务端保管密钥并调用 DeepSeek 等兼容接口。
- 财务上下文默认不发送，用户主动授权后才随提问同步；计算和对话不写入应用数据库。
- 输入校验、来源白名单、请求大小与消息角色校验、基础实例限流和上游超时处理。

## 快速开始

要求 Node.js 24 或以上、npm。仓库提供 `package-lock.json` 锁定依赖。

```sh
npm ci
npm run verify
npm start
```

打开 `http://127.0.0.1:4180/`。无需模型密钥即可使用计算器；AI 未启用时显示服务状态，不生成模拟模型答复。

开发页面可用 `npm run dev`。生产构建为 `npm run build`，生成的 `dist/` 由 `npm start` 提供服务。仅运行 `npm run preview` 可以预览前端，不包含 AI 接口。

## 启用 AI

将 `.env.server.example` 复制为 `.env.server`，在本机或部署平台配置服务端变量：

| 变量 | 用途 |
| --- | --- |
| `AI_API_KEY` | 模型服务的 API 密钥，仅在服务端使用 |
| `AI_API_BASE_URL` | 兼容 Chat Completions 的 HTTPS 服务地址 |
| `AI_MODEL` | 服务商与账号支持的模型名称 |
| `AI_ALLOWED_ORIGINS` | 允许调用的完整站点来源，多个用逗号分隔 |
| `HOST`、`PORT` | 服务监听地址及端口 |

`.env.server` 已被忽略，不得提交到 Git。不要把模型密钥写入任何 `VITE_*` 变量、前端代码或提交材料。线上环境应使用平台的秘密变量管理，并通过 HTTPS 反向代理提供访问。

详见 [部署说明](docs/DEPLOYMENT.md)。

## 算法摘要

所有输入和输出金额单位为 **万元人民币**，显示结果保留两位小数。

```text
年度支持缺口 = 有受扶养人时 max(0, 家庭必要年支出 - 其他成员承担支出)，否则为0
定寿总需求 = 房贷余额 × 本人责任比例 + 年度支持缺口 × 支持年限 + 其他债务 + 专项储备
重疾总需求 = 治疗自费储备 + 本人年收入 × 收入中断年限 + 康复储备
参考目标 = max(0, 对应总需求 - 分配给该风险的流动资产)
待补缺口 = max(0, 参考目标 - 对应已有有效保额)
```

两项资产分配超出可动用资产时按比例缩放，避免同一资产重复抵扣。年龄用于适用范围与输入校验，未作为保额系数；家庭人数用于人数关系校验，受扶养人数决定是否计入家庭支持开支。本模型不估算疾病发生率、保费或承保资格。

验收样例：年收入20万、房贷100万、家庭3人且受扶养2人、年支出12万、支持10年、定寿已有50万、定寿分配资产20万。结果为定寿目标200万、缺口150万；重疾治疗30万、康复10万、停工2年、已有20万且未分配资产，结果为目标80万、缺口60万。

## 验证与材料

执行 `npm run verify` 可运行后端处理器类型检查、自动测试、前端类型检查及生产构建。浏览器与真实模型调用记录见 [验证记录](docs/TESTING.md)。

提交材料以 `outputs/` 为准，PDF 与源码包应保持同一版本。妙搭生成代码是初始基础；当前仓库经过依赖精简、算法修复、服务端适配和验证，本地修改不会自动同步到妙搭托管版本。项目管理页面不能当作免登录应用演示链接。

## 安全边界与已知限制

- 免登录访客可以测算和提问，没有应用内管理员后台；运维权限由部署主机或托管平台控制。
- 来源检查是浏览器调用约束，不等同于用户身份认证。实例限流不能替代多实例统一配额或模型账号预算。
- 用户授权后，提问及选定财务摘要将发给所配置模型服务；服务商的数据留存政策需部署方核实。
- AI 可能出错，报告金额仍以确定性计算器为准；提示词约束不能保证模型永不偏离。
- 构建仍有大体积脚本提示；依赖审计结果只表示检查时未报告已知漏洞。

GitHub 仓库由项目维护者通过 GitHub Desktop 发布；当前说明不预设仓库地址或访问权限。
