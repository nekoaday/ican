# 部署说明

## 1. 安装与验证

使用 Node.js 24+ 和 npm，在项目根目录执行：

```sh
npm ci
npm run verify
npm start
```

`verify` 包含后端处理器类型检查、自动测试、前端类型检查和 Vite 生产构建。默认地址为 `http://127.0.0.1:4180/`。源码 ZIP 已带验证后的 `dist/`，可先运行 `npm start` 浏览；修改源码后应重新构建。

## 2. 模型服务配置

从 `.env.server.example` 创建 `.env.server`，填写自己的模型密钥、HTTPS 服务地址、模型和允许的来源。Node 启动脚本会读取 `.env.server`；也可以直接使用部署平台注入的环境变量。密钥不属于前端构建变量。

DeepSeek 示例使用 `https://api.deepseek.com` 和 `deepseek-flash`；模型名应以账号实际可用列表为准。模型服务只在收到用户提问时调用；用户可选择是否同步基准报告。

来源必须完整匹配，例如 `https://insure.example.com`，不包含路径。应用要求 AI 请求带有允许的 `Origin`；这是一项来源约束，不是账号鉴权。

## 3. 公网部署

将项目部署到支持 Node.js 24 的服务器或容器环境。安装并构建后，设置 `HOST=0.0.0.0`、平台要求的 `PORT`，并通过 HTTPS 反向代理访问。将实际域名加入 `AI_ALLOWED_ORIGINS`。

应保留同源路径 `/api/chat` 的转发，前端静态文件与 API 一起由本项目服务提供。仅把 `dist/` 上传到静态网站可运行测算页面，但不会自动获得模型代理能力。

服务器为网页设置内容安全策略、禁止嵌入和 MIME 嗅探等响应头。`vite preview` 只适合本地查看构建，不是本项目 AI 服务端。

## 4. 部署验收

1. 在未登录浏览器中打开实际应用域名，确认不是项目编辑器链接。
2. 输入 README 样例，核对200/150万与80/60万。
3. 切换三个情景，展开明细，核对使用的是情景实际年限。
4. 检查手机视口，使用打印按钮保存报告。
5. 验证 AI 未启用时提示清楚；配置后完成一次真实提问及多轮跟进。
6. 授权默认关闭；打开授权后，确认发送范围为问题及测算摘要。
7. 核对反向代理 HTTPS、来源白名单、账号费用预算和日志脱敏。

## 5. 运维与权限

访客没有部署、密钥读取或修改系统配置的入口。运维人员通过主机或托管平台管理环境变量和版本，需限制该平台的协作者权限。当前没有自建用户账号、管理员后台或数据库。

接口按单进程/实例限制每分钟30次有效模型请求、最多2个并发上游调用，正文上限16KiB，消息最多12条且每条1500字符，上游超时20秒。多进程、多实例或公网大流量部署需要补统一配额与防滥用措施。

## 6. 版本与材料一致性

比赛提交的 PDF、演示截图和源码应使用同一版本。修改本仓库不会自动修改妙搭线上版本。若另用妙搭演示，应重新核对功能和算法，避免演示与源码不同。

参考：[Vite 生产构建](https://vite.dev/guide/build.html)、[DeepSeek API](https://api-docs.deepseek.com/)。
